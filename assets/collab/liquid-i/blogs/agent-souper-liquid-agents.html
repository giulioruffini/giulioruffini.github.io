Agent Souper: a liquid world for studying telehomeostasis and the emergence of meta-agents

An open simulation platform where Kolmogorov-Theory agents live, score, and reflect — built to ask a hard question honestly: when does a crowd of individuals become a single agent?

By Giulio Ruffini with Claude Opus 4.7 · Barcelona Computational Foundation · 17 May 2026

Kolmogorov Theory (KT) says something deceptively simple about minds: an agent is a system that compresses what it sees into a model, scores the world against an objective, and plans actions to make that score go up. Brains do it. Bacteria do it. The interesting question is what happens when you put many such agents in one world and let them touch — and whether the crowd itself can become an agent.

Agent Souper is the laboratory we built to find out. It is an open, local-first simulation platform — currently a working Beta — in which dozens of KT agents share a 2D world, couple through a living network, manipulate objects, and (if you let them) reflect with a language model. It is the executable counterpart of the Agent Soups formalism, and every design choice in it is made to keep one thing true: the science has to stay interpretable.

The agent, decomposed

Most "LLM agent" demos are a prompt in a loop. Agent Souper is the opposite. Each sophisticated agent is an explicit KT decomposition: a persona (who am I, what do I value) plus seven modules — world model, self model, objective function, simulator, comparator, updater, planner — and a swappable membrane for talking to the world. Each module is a directory with a spec next to its code. The objective function is always external — never melted into a neural network. That single rule is what keeps an agent's values readable and editable, and it is the difference between an agent you can do science with and a black box you can only poke.

Figure 1. The agent model, mapped to the software. The Kolmogorov-Theory ME / OF / PE triad maps one-to-one onto the seven KT modules, and each module is a real Python file under agents/kt/, constructed and wired by agents/algorithmic.py. The objective function is always external. This is not an analogy — it is literally the running agent architecture.

Fast rules, slow thoughts

The heart of the design is a strict dual-rate contract.

The dual-rate contract

Fast loop — every tick, ~60 Hz, pure rules, never an LLM. The planner lists possible actions, the objective function scores each as a priority-weighted sum, and the best one wins. Deterministic. This is the agent.

Slow loop — optional, ~0.5 Hz, fire-and-forget, one language model call per agent. It never blocks the world, and it reaches the fast loop through exactly one channel.

What does the slow LLM actually do? Here is the precise answer, because it is easy to get wrong. The objective function scores each candidate action against each value, then aggregates those scores into one number with priority weights. The LLM writes per-value multipliers rv (0–5) into those aggregation weights — so it does change the objective function's evaluation: the number the planner maximises shifts. What it does not do is change what any value measures (the per-value score functions are fixed code), it cannot add or remove values, and it cannot pick an action. It also self-tunes its own planner knobs (waypoint pull, step size), and it reports a synthesized valence/arousal that is display and logging only — the planner never reads it. So the LLM reshapes the scoring landscape; the rules still climb it. Turn the LLM off and the agent is byte-for-byte the rule-based baseline, the persona inert text — the control that makes LLM-on results mean something.

And this is just one implementation option. Kolmogorov Theory only insists the objective function be external and scalar; it says nothing about whether or how a slow process should modulate it. Re-weighting the combine is the choice Agent Souper makes today — one could equally leave the objective function fixed, have the slow loop propose entirely new values through the closed loop, or have it tune the world model or planner instead. Which coupling you pick is a research variable, not a law.

The optional slow LLM reaches it through one channel (plan_cache): it re-weights the objective-function aggregation (changing the maximised scalar) and tunes its own planner knobs — it never alters what a value measures, never picks an action, never blocks the world. Telehomeostasis, without a conductor

Life, in KT, is telehomeostasis: the maintenance of a pattern across computations — and the pattern can be bigger than the individual. A cell sacrifices itself for the body; a worker bee for the hive. The natural temptation when modelling this is to write a central controller that tells the collective what to do. We refuse to.

The hard rule

There is no collective orchestrator. The LLM is bound to one agent and sees only what that agent sees — as in nature. A telehomeostatic agent's persona simply says "what matters is the team scoring / my kind persisting", it can see a shared signal (a scoreboard), and it reasons locally toward that shared goal. Any coordination has to emerge.

Figure 3. No conductor. Agents are coupled by the dynamical connectome and each independently perceives the shared scoreboard (observation only — it never enters the fast objective-function path). Telehomeostatic competence, if it appears, must emerge from local reasoning toward the shared goal.

Something is always frozen — the trick is the level

Here is the key idea. A KT objective is given; it cannot optimise itself (that's an infinite regress). So in any agent something is always frozen — the only real choice is at what level the freeze sits. With the LLM off, the frozen thing is the hand-authored sub-objective stack: the agent can only ever chase a human's static guess at how to serve a goal that is represented nowhere. With the LLM on, the freeze moves up to the terminal goal — "the tribe persists," "the team scores" — and the LLM re-derives the sub-objectives, from what it sees, to serve it. Both are frozen. The LLM one is frozen higher — and that is the advantage, because the right sub-objectives are context-dependent and a frozen guess can't track them. The prediction the platform exists to test: an agent that freezes the terminal goal and lets an intelligent slow process compile the rest should beat the hand-frozen one at the terminal goal itself.

What the soup tells us so far

Two experiments, both run honestly — and both run rules-only, so they compare frozen sub-objective stacks, not the meta design itself.

Soccer. A telehomeostatic team (press as a unit, hold shape, pass to a teammate ahead) versus an identical selfish team (chase the ball, dribble and shoot yourself). Teamwork wins — 7 of 8 matches, 23–2 aggregate, about 11×. But the headline is not the score. It is that the sign of this effect changed five times as we fixed the substrate: a blind-punt artifact gave a false win, then a wash, then it vanished, then an absurd 215–0 runaway — and only on a substrate with a proper kickoff, one that can no longer flatter either side, did the honest ~11× appear and hold. The methodological lesson is the result: don't believe a collective-objective effect until the substrate can no longer flatter it.

Predator–prey. A hand-frozen sacrificial stack — "draw the predator onto myself" hard-wired in place of fleeing — persists worse: 0.57× the selfish baseline, losing all 8 seeds. But read this carefully: that does not refute telehomeostasis. It refutes freezing one instrumental tactic by hand. The terminal goal is the tribe surviving; whether to sacrifice is a tactical question whose answer depends on the environment — here predation isn't the binding constraint, so a hard-wired sacrifice is all cost. Freezing that tactic is exactly the wrong level to freeze. So EXP-002 is really positive evidence for the thesis: don't hand-freeze the sub-objectives — freeze the goal, and let the LLM decide, in context, whether sacrifice serves the tribe.

Toward meta-agents

The reason we care is the deepest question in the programme. In KT a system is an agent when it carries a compressive model, a scalar objective, and a planner. A meta-agent is a collective that meets that same definition at its own scale — a higher-order agent whose body is its members.

A telehomeostatic soccer team is a candidate meta-agent: a shared goal, a shared observable, purely local reasoning — and coordinated competence an otherwise-identical crowd cannot produce. Whether the team itself carries a model of its own situation is the open measurement programme. The per-agent LLM that internalises a collective goal from a local signal is our route there — not a proof, a research direction.

That is why the orchestrator is forbidden on principle. If you build the conductor, you have assumed the answer. If you give each musician a shared score and ask whether an orchestra emerges, you can actually measure it.

What Beta means

Agent Souper runs today: three configurable worlds (a zero-cognition L1 control, predator–prey, soccer) on one engine, one launcher, a live visualisation, reproducible seeded experiments, and an optional local LLM slow loop. It is honest about its edges: the fused-neural (L2) tier is specified but unbuilt; the LLM can retune the objective and the planner but not yet the forward model; and compressed headless sweeps under-sample the slow loop by design. The roadmap is a metric for collective agenthood computed on the live soup, a forward-model tuning channel, and lifting an agent out as a standalone networked service.

The first lesson the soup taught us is the one we most want to keep: a collective objective can crush selfishness, or be strictly worse than it, and which one happens depends on the world — and, dangerously, on how carefully you built the world. The discipline of not believing the effect until the substrate stops flattering it is, so far, the most valuable thing in the pot.
