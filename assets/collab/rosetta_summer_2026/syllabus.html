Rosetta Stone of Neural Mass Models — internship syllabus for Lucia & Claudia

One shared week of AI, neural networks, and LLMs, calibrated to a strong mathematics background. Then a guided implementation of the model ladder — from harmonic oscillators to next-generation mean fields — ending in two public artefacts.

Tutors: Francesca Castaldo & Giulio Ruffini · Neuroelectrics / BCOM · June 2026

Start: June 2026 (Week 1 shared) Duration: Lucia 4 wks · Claudia 8 wks Location: Neuroelectrics, Barcelona Shared folder: Google Drive

“Understanding is the ability to see one thing in many ways.”

— R. P. Feynman, opening of the Rosetta Stone paper

This internship has two parts. Week 1 is a shared crash course in AI, neural networks, large language models, and the practical use of Claude as a research tool — calibrated to a strong pure-mathematics / mathematical-physics background. From Week 2 onward you each work on the Rosetta Stone of Neural Mass Models paper: reading it carefully, then implementing the model ladder it describes and producing a public-facing artefact. Lucia's headline deliverable is a BCOM-style website that is the paper; Claudia's is a deeper implementation that extends Lucia's scaffold.

1 · Goals & learning outcomes

By the end of the internship you should be able to:

  1. Explain, at the level of a mathematician new to the field, what neural networks and large language models are, what they optimise, and what their structural priors are.
  2. Use Claude (and one other frontier coding assistant of your choice) as a working collaborator — reading code, designing experiments, drafting documentation — without losing your own grasp of the problem.
  3. Read the Rosetta Stone paper closely enough to reconstruct its derivation ladder: harmonic oscillator → Stuart–Landau → Wilson–Cowan → NMM1 (Jansen–Rit / laminar) → NMM2 (Montbrió–Pazó–Roxin).
  4. Implement at least three models from that ladder in clean, tested Python, with reproducible figures, and embed them in a small open-source repository.
  5. Produce a public-facing artefact — Lucia owns a simple BCOM-styled site presenting her NMM1/NMM2 implementations; Claudia contributes the nmmlab package and a notebook gallery for the lower-rung models.

2 · Logistics & working rhythm

Cadence

  • Daily standup (15 min, asynchronous Slack thread or a short call): yesterday / today / blockers.
  • Weekly sync (60 min, with Francesca and Giulio): walk through code, demo figures, plan the next week.
  • One paper presentation per intern at the end of the programme (Claudia gets a mid-internship demo as well).

Tools

  • Python 3.11+ with numpy, scipy, matplotlib, jupyter. That's the whole stack — no framework hunting.
  • Git + GitHub; one repo per intern.
  • Claude (desktop or web) as the primary AI collaborator.
  • Plain HTML / CSS / JavaScript for the website — no build step, no framework. BCOM palette: Lively Blue #002878 and Coral #FF6657 (copy from bcom.one).

Hosting the website

GitHub Pages is the default: free, lives next to your code, auto-rebuilds on every push. Enable it in repo Settings → Pages, point it at main branch /docs folder, and your site is live at https://<your-name>.github.io/<repo>/ within minutes. Claude can run the whole setup for you — just ask. Alternatives if you ever outgrow Pages: Netlify or Cloudflare Pages. Pick one and move on.

GitHub Pages serves static files only — HTML, CSS, JS, images. There is no Python interpreter on the server. So write your simulations in Python locally, generate the figures, and embed them. For interactive demos where a slider changes the dynamics live, port the Python ODE solver to JavaScript — see the green box below.

Yes — HTML5 can solve your ODE and plot it. Here's the workflow.

Every model in the Rosetta ladder — HO, DHO, SL, WC, JR, NMM2 — is small enough to integrate in real time in plain JavaScript on any modern browser. The pattern:

  1. Build and verify in Python first. Write the ODE, integrate with scipy.solve_ivp, plot with matplotlib. Confirm you see the expected behaviour. This is your ground truth.
  2. Ask Claude to port it. One sentence: "port this Python ODE to a single self-contained HTML file with vanilla JS + Plotly, three parameter sliders, an RK4 integrator, matching the default-parameter Python output." Claude produces one .html file, ~200 lines, no build step.
  3. Verify side-by-side. Python and HTML at default parameters — traces should look identical.
  4. Deploy. Drop the file in /docs/, push, refresh the live URL.

The JS stack is tiny: a hand-rolled RK4 (~30 lines), Plotly.js from a CDN, <input type="range"> sliders. Single-node models run at hundreds of thousands of steps per second in the browser. One <script> tag, no dependencies.

House rule on AI use

You may use Claude for anything — but every line of code or prose you submit, you must be able to explain and defend. If you can't reconstruct the reasoning without the assistant, the work isn't yours yet. Treat the AI like a very fast, occasionally wrong, very patient collaborator.

3 · Phase 1 · Week 1 — AI / NN / LLM crash course shared

The aim of Week 1 is not to make you ML engineers — it is to give you the conceptual handles you need so that, when an LLM proposes code or an architecture, you can judge it. We assume strong calculus, linear algebra, probability, and (for Lucia) measure theory. We will not assume any prior Python ML.

Day 0 — Accounts & scaffolding (do this on or before Day 1)

Spend a couple of hours getting the writing and code stack in place. Claude can walk you through every step below — creating accounts, initialising a repo, writing your first commit, even drafting an Overleaf project skeleton. Just ask in plain English ("help me create a GitHub repo for my internship and make my first commit") and Claude will give you the exact commands and explain what each one does.

Create accounts

  • Overleaf — your home for writing (memos, notes, the eventual Rosetta-Stone companion text). Free tier is fine; the BCOM/UPF group licence covers premium features if you need them.
  • GitHub — your home for code. Use your real name and a professional handle.
  • Claude (web + desktop) — sign in to the workspace Francesca shares with you. Install the desktop app so you can use Cowork on local files.

Scaffold your Overleaf notebook

  • Create one personal Overleaf project, <your-name>-notebook-2026, structured as: main.tex + one week-N.tex input per week, plus a refs.bib. A simple \input{} per week keeps things tidy.
  • This is where the Week-1 memo, weekly notes, and any derivations you do by hand will live. Treat it as a working lab notebook, not a polished document.
  • For backup, download the project zip from Overleaf at the end of each week and drop it in the shared Drive. (Overleaf's git/GitHub sync is a paid feature — don't worry about it unless we enable the group licence.)

Scaffold your GitHub repo

  • Create one personal repository, <your-name>-internship-2026, with this layout: 
    README.md          ← goals, week-by-week log
CLAUDE.md          ← style preferences, vocabulary, do-not-do rules
notes/             ← markdown notes, exported memos
code/              ← Python scripts and modules
notebooks/         ← Jupyter notebooks (one per experiment)
figures/           ← exported figures (svg, png, pdf)
memo/              ← end-of-week memo source
  • The CLAUDE.md starts tiny — three or four rules — and grows as you discover what you want Claude to do or not do. Treat it as a living style guide.

Learn the basic Git loop

  • Four commands, that's it for now: git clone, git add, git commit -m "...", git push. Claude will explain each one if you ask, and show you a short, clean session.
  • One step up: feature branches and pull requests. git checkout -b feature/dho-sim, push, open a PR against main. We will use PRs for the Phase-2 work so Francesca and Giulio can leave inline comments.
  • Set up an SSH key for GitHub (one-off, Claude will guide you) so you stop typing passwords.

House style (memorise these — they apply for the rest of the internship)

  • Commit messages: short, imperative ("add DHO simulation", "fix typo in §2"). One commit per logical change.
  • Every notebook starts with a one-paragraph cell explaining what it does and which figure or claim it produces.
  • Never paste credentials, API keys, or patient data into a repo. If you do by accident, tell us immediately — we rotate the key, no drama.
  • Push at least once a day. If it isn't on GitHub, it doesn't exist.

Day 3 — Embeddings: meaning as geometry

Before attention, before transformers — the most important idea in modern NLP is that words, sentences, and concepts can be mapped to points in a high-dimensional vector space where geometry encodes meaning. This is the conceptual lever you need to read the rest of the field.

Read

  • Vicki Boykis, What are embeddings? — free PDF, ≈100 pages but very readable. Read §1–3 today; the rest is great Phase-2 weekend reading. mathematician-friendly
  • Optional: Jay Alammar, The Illustrated Word2vec — pictures-first companion piece.

Watch

  • 3Blue1Brown, But what is a GPT? Visual intro to transformers — the first half is the best intuition pump for embeddings on the internet. Pay close attention to the word-vector arithmetic (king − man + woman ≈ queen). ~27 min

Do

  • pip install sentence-transformers, load all-MiniLM-L6-v2, embed a dozen sentences of your choice. Compute the pairwise cosine-similarity matrix and plot it as a heatmap. Do synonymous sentences cluster? What about sentences about neurons vs. sentences about oscillators?
Day 4 — Attention and transformers

Watch

  • 3Blue1Brown, Attention in transformers, visually explained. ~27 min
  • Optional: 3Blue1Brown, How might LLMs store facts? (MLPs in transformers).

Read

  • Optional / reference: Vaswani et al. (2017), Attention is All You Need — read §3, skim the rest.

Do

Anchor concepts from the How Claude Works slides

Predict-next-token = compression = world model. A predictor that good must compress; a compressor that good must model. The frozen weights are an implicit world-model — that's what makes the prompt stack worth designing.

Two parts working together. A trained model is frozen weights (what it knows) plus your markdown — CLAUDE.md, SKILL.md, your message — read fresh every session (how it behaves today).

The model is stateless. Memory lives in the application, not the model. Every turn, the host reconstructs the full context and resends it.

Implement it twice: once solo, once pair-programming with Claude. Write a half-page note comparing the two sessions: what was faster, what was wrong, what you learnt about prompting.

4 · Phase 2 · Rosetta Stone implementation

The paper — Rosetta Stone of Neural Mass Models (view-only Overleaf; LaTeX source also in resources/TN0366___Rosetta_Stone_of_Neural_models/main.tex) — walks a ladder of neural mass models, each rung introduced first as an isolated node, then under forcing, then in coupled networks. Phase 2 asks you to walk that same ladder in code.

Friendly entry points to read first, before diving into the paper:

  • Giulio Ruffini, The Rosetta Stone of Neural Mass Models — a short blog companion to the paper. Read it before §1 of the paper to know what you're getting into.
  • Giulio Ruffini, What Is an Oscillation, Really? Topology, Compression, and the Circle at the Heart of Brain Rhythms — the deep structure of oscillations. This is the conceptual frame for every rung of the ladder; read it on the first Monday of Phase 2.

4.1 · Lucia 4 wks · 3 on Rosetta

Mission · Lucia

Read the paper carefully and push down the ladder as far as you can: NMM1 (Jansen–Rit, and the laminar variant if time allows) and then NMM2 (Montbrió–Pazó–Roxin). You also maintain a simple BCOM-styled companion website — but keep it spartan; the implementations are the headline. Two clean simulation pages with one runnable demo each is enough.

Week 2 — Read the paper end-to-end + set up the scaffold

Read

  • Rosetta Stone paper §1–§5 lightly (you already covered §2 conceptually in Phase 1), then §6 (NMM1) carefully — slowly, with pen and paper. Reproduce the second-order PSP equation and the Jansen–Rit closed loop on paper.
  • Giulio Ruffini, Synapses as Springs: Linear Operators, Green–Laplace Tools, and the Origin of E–I Oscillations — read this before tackling §6. The second-order PSP filter in JR is exactly the "spring" the blog describes.

Do

  • Spin up a fresh repo rosetta-nmm-site. Set up the site skeleton in BCOM style (one page each for §6 and §7, blue header + coral accent), deployed to GitHub Pages on push. Don't fuss over visuals yet.
  • Implement a sanity-check DHO with forcing in code/, just to confirm scipy.integrate.solve_ivp works on your machine. Reproduce the §2 resonance curve. One day max.

Milestone

  • Friday demo: skeleton site online, integrator stack working, §6 read and summarised in 1 page.
Week 3 — NMM1 (Jansen–Rit, with a laminar stretch)

Read

  • Re-read Rosetta Stone §6 in full, including the laminar extension. Rosetta §6 is the whole reading on JR — don't go back to the original Jansen & Rit 1995 paper.
  • Optional, only if you go for the laminar stretch: Sanchez-Todo, Bastos, Lopez-Sola, Mercadal et al. (2023), A physical neural mass model framework for the analysis of oscillatory generators from laminar electrophysiological recordings — the LaNMM paper.

Do

  • Implement single-column Jansen–Rit: three populations (E, P, I), second-order PSP filters, static sigmoid. Reproduce the alpha-rhythm output for canonical parameters.
  • Add an interactive page to the site — three sliders (synaptic gains, time constants) and the live LFP trace.
  • Stretch: implement the laminar variant from Sanchez-Todo et al. — even a stripped two-layer version is meaningful.

Milestone

  • Friday demo: a JR simulation runs in the browser-embedded notebook, alpha peak visible.
Week 4 — NMM2 if you can + write-up + presentation

Read

  • Rosetta Stone §7 (NMM2) — the hardest section. This is enough; you do not need to go back to Montbrió–Pazó–Roxin (2015) directly.
  • Optional reference only if Rosetta §7 leaves something unclear: Montbrió, Pazó & Roxin (2015), Macroscopic description for networks of spiking neurons.

Do

  • Implement the Montbrió–Pazó–Roxin (r, v) mean-field equations for a QIF population. Reproduce one figure from §7 (e.g. the spiking-vs-mean-field comparison). If time runs short, document where you got to — partial NMM2 with honest commentary beats a rushed full implementation.
  • Polish the site to a clean MVP: README, citation page crediting Castaldo, de Palma Aristides, Clusella, Garcia-Ojalvo & Ruffini, MIT or CC-BY licence, and one short "what I learnt" page.
  • Prepare a 20-minute final presentation: what you read, what you built, the failure modes you hit, what you would do with another four weeks.

Final deliverables (Lucia)

  1. A clean (not heavily polished) BCOM-styled site on GitHub Pages with at least the NMM1 page live, NMM2 page if reached.
  2. Working implementations of Jansen–Rit (required) and Montbrió–Pazó–Roxin (target). Laminar NMM1 is a stretch goal.
  3. Source repo with README and licence; final presentation + 1-page reflection memo.

4.2 · Claudia 8 wks · 7 on Rosetta

Mission · Claudia

Build a clean, well-tested foundation: a Python package nmmlab that implements the lower rungs of the ladder — harmonic oscillator (HO), damped HO, Stuart–Landau (SL), and optionally Wilson–Cowan (WC). Quality over breadth: type hints, pytest coverage, CI green, a notebook gallery reproducing each paper figure, and clear documentation so future students (or Lucia mid-internship) can build on it.

Weeks 2–3 — Read the paper + scaffold the package + HO/DHO

Read

  • The full Rosetta Stone paper, end-to-end, lightly. Write a 2-page "map of the paper" showing which sections you understand fully, partially, or not at all.
  • Rosetta Stone §2 (linear response, phase-only limits) — carefully, pen-and-paper.
  • Strogatz, Nonlinear Dynamics and Chaos, Chs. 4–5 (phase plane and bifurcations) — reference as needed.

Do

  • Set up nmmlab: uv- or poetry-managed Python package; pytest + ruff from day 1; type hints; GitHub Actions CI; one-line install.
  • Design a shared Simulator interface (state, step, integrate) that every later model will subclass — this is your reusable substrate.
  • Implement nmmlab.ho and nmmlab.dho (undamped + damped harmonic oscillators, with and without sinusoidal forcing). Reproduce §2 figures: phase portrait, resonance curve, transient + steady-state traces.

Milestone (end of W3)

  • Two models, ≥90% test coverage, two reproduced figures, CI green, README rendered nicely on GitHub.
Weeks 4–5 — Stuart–Landau + the synapse/transfer interlude

Read

  • Rosetta Stone §3 (Stuart–Landau) and §4 (synapses and transfer functionals) carefully.
  • Giulio Ruffini, Synapses as Springs: Linear Operators, Green–Laplace Tools, and the Origin of E–I Oscillations — read alongside §4; it makes the operator formalism click.
  • Pikovsky, Rosenblum & Kurths, Synchronization, Chs. 1–3 (in the resources folder).

Do

  • Implement nmmlab.sl: integrate the complex Stuart–Landau equation. Reproduce the Hopf bifurcation diagram sweeping μ; the limit-cycle radius vs. μ; the phase-amplitude decomposition.
  • Implement nmmlab.synapse: first- and second-order linear filters with the operator formalism from §4.1 — even though you don't reach NMM1 yourself, the synapse module is the bridge Lucia will use.
  • Extend SL to a coupled-oscillator network on a small toy connectome (e.g. 6 Kuramoto-style nodes) and reproduce the corresponding §3 coupling subsection figure.

Milestone (end of W5)

  • Mid-internship presentation (45 min) to Francesca and Giulio: walk through nmmlab's API design, the three models so far, what surprised you, where you would push next.
Weeks 6–7 — Coupled networks, notebook gallery, optional Wilson–Cowan

Read

  • Rosetta Stone §5 (Wilson–Cowan) — read it carefully; whether you implement it depends on Week 5's progress. Rosetta is enough on the model; don't go back to Wilson & Cowan 1972 unless you're curious.

Do

  • Build the notebook gallery: one Jupyter notebook per model (ho, dho, sl), each reproducing the §2/§3 figures and including a short narrative cell explaining the model in your own words. These notebooks are what Lucia's site will embed.
  • Add coupled-network experiments: extend HO/DHO/SL to small graphs, document phase synchronisation onset.
  • Optional, if pace allows: implement nmmlab.wilco (single-node Wilson–Cowan with sigmoid transfer; reproduce the limit cycle in the (E, I) plane and the Hopf locus).
Week 8 — Polish, write-up, presentation

Do

  • Ship nmmlab v0.1: tagged release on GitHub, optional PyPI publication. Final README with install instructions, model overview, and a "how to extend up the ladder" section pointing at Lucia's NMM1/NMM2 work.
  • Wire the gallery into Lucia's site — one notebook per model, exported to plain HTML with jupyter nbconvert.
  • Final presentation (45 min) + reflection memo (2 pages): what would the next student need to do to climb to NMM1/NMM2 cleanly, given the substrate you built?

Final deliverables (Claudia)

  1. nmmlab Python package, tagged v0.1, installable from GitHub, with HO + DHO + SL (and optionally WC). Type hints, tests, CI.
  2. Notebook gallery reproducing the key §2 and §3 figures, embedded in Lucia's website.
  3. Final presentation + reflection memo.
