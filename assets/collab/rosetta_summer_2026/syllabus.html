Rosetta Stone of Neural Mass Models — internship syllabus for Lucia & Claudia

One shared week of AI, neural networks, and LLMs, calibrated to a strong mathematics background. Then a guided implementation of the model ladder — from harmonic oscillators to next-generation mean fields — ending in two public artefacts.

Tutors: Francesca Castaldo & Giulio Ruffini · Neuroelectrics / BCOM · June 2026

Start: June 2026 (Week 1 shared) Duration: Lucia 4 wks · Claudia 8 wks (starts 1 wk earlier) Hosted by: Neuroelectrics × BCOM, Barcelona Shared folder: Google Drive

“Understanding is the ability to see one thing in many ways.”

— R. P. Feynman, opening of the Rosetta Stone paper

This internship has two parts. Week 1 is a shared crash course in AI, neural networks, large language models, and the practical use of Claude as a research tool — calibrated to a strong pure-mathematics / mathematical-physics background. From Week 2 onward you both work on the Rosetta Stone of Neural Mass Models paper: reading it carefully, then implementing the model ladder it describes. The code (nmmlab) and the public website are both joint deliverables — one shared repo, both push, NE × BCOM co-branded.

1 · Goals & learning outcomes

By the end of the internship you should be able to:

  1. Explain, at the level of a mathematician new to the field, what neural networks and large language models are, what they optimise, and what their structural priors are.
  2. Use Claude (and one other frontier coding assistant of your choice) as a working collaborator — reading code, designing experiments, drafting documentation — without losing your own grasp of the problem.
  3. Read the Rosetta Stone paper closely enough to reconstruct its derivation ladder: harmonic oscillator → Stuart–Landau → Wilson–Cowan → NMM1 (Jansen–Rit / laminar) → NMM2 (Montbrió–Pazó–Roxin).
  4. Implement at least three models from that ladder in clean, tested Python, with reproducible figures, and embed them in a small open-source repository.
  5. Produce two joint public artefacts: a co-developed Python package (nmmlab) covering the model ladder, and a co-developed NE × BCOM-styled website that presents the implementations and runnable demos. One shared repo, both interns push.

You may use Claude for anything — but every line of code or prose you submit, you must be able to explain and defend. If you can't reconstruct the reasoning without the assistant, the work isn't yours yet. Treat the AI like a very fast, occasionally wrong, very patient collaborator.

3 · Phase 1 · Week 1 — AI / NN / LLM crash course shared

The aim of Week 1 is not to make you ML engineers — it is to give you the conceptual handles you need so that, when an LLM proposes code or an architecture, you can judge it. We assume strong calculus, linear algebra, probability, and (for Lucia) measure theory. We will not assume any prior Python ML.

Pacing — note for Claudia

Claudia starts one week before Lucia. Treat the Week-1 material as 1.5 to 2 weeks at your pace, not a single sprint. The material is dense; the extra time is for you to absorb AI + Claude basics properly before Phase 2 begins. By the time Lucia arrives, you should be comfortable with the Anthropic Academy courses, basic Claude workflows, and the Git loop.

Day 3 — Embeddings: meaning as geometry

Before attention, before transformers — the most important idea in modern NLP is that words, sentences, and concepts can be mapped to points in a high-dimensional vector space where geometry encodes meaning. This is the conceptual lever you need to read the rest of the field.

Read

  • Vicki Boykis, What are embeddings? — free PDF, ≈100 pages but very readable. Read §1–3 today; the rest is great Phase-2 weekend reading. mathematician-friendly
  • Optional: Jay Alammar, The Illustrated Word2vec — pictures-first companion piece.

Watch

  • 3Blue1Brown, But what is a GPT? Visual intro to transformers — the first half is the best intuition pump for embeddings on the internet. Pay close attention to the word-vector arithmetic (king − man + woman ≈ queen). ~27 min

Do

  • pip install sentence-transformers, load all-MiniLM-L6-v2, embed a dozen sentences of your choice. Compute the pairwise cosine-similarity matrix and plot it as a heatmap. Do synonymous sentences cluster? What about sentences about neurons vs. sentences about oscillators?
Day 4 — Attention and transformers

Watch

  • 3Blue1Brown, Attention in transformers, visually explained. ~27 min
  • Optional: 3Blue1Brown, How might LLMs store facts? (MLPs in transformers).

Read

  • Phuong & Hutter (2022), Formal Algorithms for Transformers — §1–3, dimension-check carefully. This is the mathematician's entry point. required
  • Optional / reference: Vaswani et al. (2017), Attention is All You Need — read §3, skim the rest.

Do

  • On paper: write out a single self-attention head as a linear-algebraic expression. Verify dimensions (Q, K, V) → softmax(QKᵀ/√d) · V for a toy batch.

Anchor concepts from the How Claude Works slides

Predict-next-token = compression = world model. A predictor that good must compress; a compressor that good must model. The frozen weights are an implicit world-model — that's what makes the prompt stack worth designing.

Two parts working together. A trained model is frozen weights (what it knows) plus your markdown — CLAUDE.md, SKILL.md, your message — read fresh every session (how it behaves today).

The model is stateless. Memory lives in the application, not the model. Every turn, the host reconstructs the full context and resends it.

4 · Phase 2 · Rosetta Stone implementation

The paper — Rosetta Stone of Neural Mass Models (view-only Overleaf; LaTeX source also in resources/TN0366___Rosetta_Stone_of_Neural_models/main.tex) — walks a ladder of neural mass models, each rung introduced first as an isolated node, then under forcing, then in coupled networks. Phase 2 asks you to walk that same ladder in code.

Friendly entry points to read first, before diving into the paper:

  • Giulio Ruffini, The Rosetta Stone of Neural Mass Models — a short blog companion to the paper. Read it before §1 of the paper to know what you're getting into.
  • Giulio Ruffini, What Is an Oscillation, Really? Topology, Compression, and the Circle at the Heart of Brain Rhythms — the deep structure of oscillations. This is the conceptual frame for every rung of the ladder; read it on the first Monday of Phase 2.

The shape of Phase 2 is four words: read, implement, play, demo. We do not prescribe the week-by-week — you set the pace at the Tuesday/Thursday Norrsken meeting with Francesca and Giulio. The plan below is the shape, not a schedule.

Read

Both of you read the entire Rosetta paper — every section, every model. Two close readers catch what one misses. Start with Giulio's two friendly entry-point blogs in the Phase-2 reading list, then the paper itself. Pen and paper for the equations you don't follow on first pass.

Implement

The code lives in one shared package — nmmlab — which both of you co-develop. You split the ladder rungs between you for focus, but the package, its tests, and its API are owned by the team. Push to the same repo, review each other's PRs.

  • Claudia focuses on the foundational rungs — HO (with DHO) and Wilson–Cowan. Clean Python, reproducible figures, notebooks that someone else can re-run. The extra time and the more junior level go into doing this well.
  • Lucia focuses on the harder dynamics — Stuart–Landau and NMM1 (Jansen–Rit). NMM2 is a stretch if the rest lands cleanly.
  • Both: read every section of the paper, sit at the same table, hand work back and forth, ask each other before asking us.

Play

Once a model runs in Python, port the interesting one to HTML5 so a visitor can move a slider and watch the dynamics change. Claude does this port for you in one ask — the workflow lives at the bottom of this page (§6 Web implementation). The joint website is where these demos live.

Demo

Each of you gives a final presentation at the end of your internship — what you read, what you built, what surprised you, what you would do next. That, and the live joint website, are the public artefacts.

6 · Web implementation

Hosting. The joint website lives on GitHub Pages: free, sits next to your code, auto-deploys on every push. Settings → Pages → point at main /docs. Claude can run the entire setup for you — just ask. Alternatives if you ever need them: Netlify, Cloudflare Pages.

GitHub Pages serves static files only — HTML, CSS, JS, images. No Python on the server. So write your simulations in Python, generate the figures, embed them. For interactive demos where a slider changes the dynamics live, see below.

Yes — HTML5 can solve your ODE and plot it live. Here's the workflow.

Every Rosetta-ladder model is small enough to integrate in real time in plain JavaScript. The pattern:

  1. Build and verify in Python first. Integrate with scipy.solve_ivp, plot with matplotlib. This is your ground truth.
  2. Ask Claude to port it to a single HTML file: "port this Python ODE to a self-contained HTML page with vanilla JS + Plotly, three parameter sliders, an RK4 integrator, matching the default-parameter Python output." ~200 lines, no build step.
  3. Verify side-by-side. Python and HTML traces should be visually identical at default parameters.
  4. Deploy. Drop the file into /docs/, push, refresh the URL.

The JS stack is tiny: a hand-rolled RK4 (~30 lines), Plotly.js from a CDN, <input type="range"> sliders. One <script> tag, no dependencies. Single-node models run at hundreds of thousands of steps per second in the browser.
